# ---------------------------------------------------------------------------
# Directives first, on purpose: a parser should not have to read past a wall of
# comments to reach a rule.
#
# ⛔ DO NOT PUT "Disallow: /" BACK. It breaks the two things this site needs:
#
#   1. Link previews. Messenger, WhatsApp, Telegram and Slack crawlers respect
#      robots.txt, so a disallow yields a bare URL with no title, description or
#      image — exactly the shape of a link nobody taps, on a site whose entire
#      delivery mechanism is one person sending it to another.
#
#   2. The noindex itself. A crawler that may not FETCH the page never sees the
#      directives inside it, so a disallowed page can still be indexed from an
#      inbound link, with no snippet. Blocking the fetch defeats the exclusion.
#
# Staying out of SEARCH is done in the pages, by NAME — googlebot, bingbot,
# slurp, yandex each get "noindex,nofollow". There is deliberately no blanket
# <meta name="robots">: that form addresses EVERY robot, and a preview crawler
# reads it as "do not process this page".
#
# ⚠️ Facebook caches robots.txt for about a day, independently of the page. If a
# disallow was ever served, the debugger keeps failing after it is removed until
# that cache expires — "Scrape Again" refetches the PAGE, not this file.
# ---------------------------------------------------------------------------
